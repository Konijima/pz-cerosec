    /* The manual. Four items -- the three volumes of the set, and the single
       book that shipped before the set did -- and every key on them verified
       against the game rather than against a wiki:

       - The block syntax and the key spellings are literature.txt's
         (media/scripts/generated/items/literature.txt): Base.Book at 1704,
         Base.Journal at 1777, Base.Notebook at 1817, Base.Book_Computer at
         1837. Build 42 has no `Type =` any more -- there is not one line of it
         left in media/scripts/generated/items -- it is `ItemType = base:<kind>`
         and the kinds are zombie.scripting.objects.ItemType's constants
         (javap: ALARM_CLOCK .. WEAPON_PART).

       - ItemType is base:normal and NOT base:literature, deliberately. A
         Literature item that cannot be written on is one the vanilla inventory
         menu offers to READ (ISInventoryPaneContextMenu.lua:242 sets
         isAllLiterature for it, :539 calls doLiteratureMenu, :1107 adds the
         Read option), and vanilla's Read is a timed action: the character sits
         down and burns hours of game time on it. This book is read by the
         player, not by the character -- so the item is a plain one and the only
         thing on its menu is ours.

       - DisplayCategory is a free string that the inventory prints through
         `getText("IGUI_ItemCat_" .. item:getDisplayCategory())`
         (ISInventoryPane.lua:2532-2533), and IGUI_ItemCat_Literature is a key
         the game ships (media/lua/shared/Translate/EN/IG_UI.json:276). So a
         Normal item still files itself under Literature, which is where a book
         belongs in the list.

       - Icon = CeroSecManual resolves to media/textures/Item_CeroSecManual.png:
         Item.DoParam builds `itemName = "Item_" + icon` and asks
         Texture.trygetTexture for it (javap -c zombie.scripting.objects.Item,
         the Icon branch at 528-567), and trygetTexture turns a bare name into
         "media/textures/<name>" and then appends ".png" (javap -v -c
         zombie.core.textures.Texture, bootstrap methods 7 and 8) before handing
         it to ZomboidFileSystem, which is what looks through the mod folders.

       - StaticModel and WorldStaticModel are Base.Book's own two, verbatim.
         Every literature item in the game defines both; without the world one
         there is no model to drop on the ground.

       DisplayName is here as the fallback; the name a player actually reads
       comes from Translate/EN/ItemName.json, keyed "CeroSec.Manual" the way
       vanilla keys "Base.Book_Computer". */

    /* The floppy disks. Four of them, and the four are the same disk in four
       colours of shell -- which is how a box of them was sold in 1993 and why
       they all carry the same DisplayName: a survivor tells them apart by
       colour and by the label he writes on the state inside (`newfs`, and the
       drive's own listing), never by the name in his inventory.

       Weight is 0.1, set against the vanilla items it sits between rather than
       against a feeling: Base.Paperclip is 0.01, Base.BusinessCard 0.05,
       Base.Disc_Retail 0.3 and Base.Notebook 0.5. A 3.5-inch disk is a shell of
       stiff plastic around a sheet of mylar -- twenty grammes -- which is
       heavier than a card and lighter than a CD in its case.

       DisplayCategory is Electronics, an IGUI_ItemCat_ key the game ships
       (media/lua/shared/Translate/EN/IG_UI.json), for the same reason the
       manual files itself under Literature: the category is a free string the
       inventory prints through getText, and an unknown one prints the key.

       ItemType is base:normal and there is deliberately nothing else on these
       items -- no Tags, no MediaCategory. What a disk IS lives in its modData
       and is the OS's business; the item is the thing that carries it.

       Icon = CeroSecFloppyBlue resolves to
       media/textures/Item_CeroSecFloppyBlue.png, and WorldStaticModel =
       CeroSecFloppyBlue to the model block in models_cerosec.txt. Both names
       carry the mod's own prefix so that a world with the old Computer mod
       installed beside this one has nothing to collide over.

       The name a player reads comes from Translate/EN/ItemName.json, keyed
       "CeroSec.FloppyBlue"; the DisplayName here is the fallback, and it is
       spelled out in words because a double quote in a script value is not
       something to bet on. */

    /* The hardware modules, rung 4f.

       Four boxes a survivor screws to a door, a window or a light switch so
       that a computer can reach it (CeroSecModules.lua, and the manual's
       chapter on /dev). 1993 vocabulary and nothing invented: an electric
       strike, a door operator, a magnetic contact and a relay are what the
       trade called these four things then and what it calls them now.

       Same keys as the disks above and for the same reasons -- ItemType is
       base:normal, DisplayCategory is the Electronics the game already ships a
       name for, the DisplayName here is the fallback and Translate/EN's
       ItemName.json is what a player reads.

       WorldStaticModel names a VANILLA model in every case, the way the manual
       items name Book and BookClosedGround: this mod ships no mesh for these
       and a made-up name is an item that drops on the floor as nothing at all.
       MotionSensor for the contact (it is a sensor in a box), ElectronicsScrap
       for the relay (a board), ScrapMetal for the strike and the operator (a
       lump of metal is what either looks like lying on a road).

       The weights are set against the vanilla items they sit between rather
       than against a feeling: Base.ElectronicsScrap is 0.1,
       Base.MotionSensor 0.3, Base.SmallSheetMetal 0.5, Base.Doorknob 1.0,
       Base.HomeAlarm 1.0 and Base.SheetMetal 2.0. So: a contact is two reed
       switches in plastic, a relay is a board in a case, a strike is a door
       fitting the size of a knob, and an operator is a motor and an arm -- the
       heaviest thing in this mod and the only one a survivor thinks twice
       about carrying. */

    /* The book the four recipes come out of.

       This is the one item in the mod that IS base:literature, and it is the
       opposite of the decision the manual volumes took at the top of this file.
       They are base:normal precisely so that vanilla adds no Read of its own,
       because they are read by the player. This one is read by the CHARACTER:
       vanilla's Read is the whole mechanism, and every line of it is the
       engine's.

       - `LearnedRecipes` is the B42 spelling. There is no `TeachedRecipes` left
         anywhere in media/scripts -- not one line -- and the key the game reads
         is this one: literature.txt:5307-5320 (Base.ElectronicsMag1, which
         teaches the remote controller) and :5781-5786 (Base.MechanicMag1).

       - Reading it teaches, and no Lua of ours is involved at any point.
         IsoGameCharacter.ReadLiterature(Literature) walks
         Literature.getLearnedRecipes(), skips what getKnownRecipes() already
         contains and calls learnRecipe(String) on the rest -- javap -c
         zombie.characters.IsoGameCharacter, the ReadLiterature body at
         offsets 24-81. The Lua side only offers the option
         (ISInventoryPaneContextMenu.lua:1081 spots an item with
         getLearnedRecipes(), :1107 adds Read) and runs the timed action
         (ISReadABook, whose perform() at :194 does not learn anything: it
         closes the book).

       - Every other key on it is Base.ElectronicsMag1's, verbatim, because a
         magazine that weighs or files itself differently from the five the game
         already prints is a magazine a player can tell is a mod's:
         DisplayCategory = RecipeResource (IGUI_ItemCat_RecipeResource is a key
         the game ships, EN/IG_UI.json:284), Weight = 0.5, BoredomChange -20 and
         StressChange -15, Tags = base:magazine.

       - StaticModel = Magazine and WorldStaticModel = MagazineGround are
         Base.SmithingMag1's own two (literature.txt:12-13) and both are
         declared in vanilla: models_items.txt:281 and :4493. The five
         ElectronicsMag items each name a per-issue ground model of their own
         (MagazineElec1Ground and its four brothers) and this book is not one of
         their issues, so it takes the generic pair rather than borrowing an
         issue's cover.

       - OnCreate is vanilla's own and it does exactly one thing: javap -c
         zombie.scripting.logic.ItemCodeOnCreate.onCreateRecipeMagazine is four
         instructions long and they set modData.literatureTitle to the item's
         full type. That is what `Re-read` rather than `Read` is built on
         (ISReadABook:perform :194, isLiteratureRead) -- it does NOT rename the
         item, so the DisplayName below survives it.

       DisplayName is the fallback; ItemName.json is what a player reads, and
       Tooltip_item_CeroSecWiringGuide is in Tooltip.json beside it, the way
       Base.MechanicMag1 carries Tooltip_item_MechanicMag1
       (literature.txt:5781). */

    item WiringGuide
    {
        DisplayName = CeroSec Field Wiring Guide,
        DisplayCategory = RecipeResource,
        ItemType = base:literature,
        Weight = 0.5,
        Icon = CeroSecWiringGuide,
        BoredomChange = -20,
        StressChange = -15,
        LearnedRecipes = MakeCeroSecMagneticContact;MakeCeroSecRelay;MakeCeroSecElectricStrike;MakeCeroSecDoorOperator,
        Tooltip = Tooltip_item_CeroSecWiringGuide,
        StaticModel = Magazine,
        WorldStaticModel = MagazineGround,
        Tags = base:magazine,
        OnCreate = ItemCodeOnCreate.onCreateRecipeMagazine,
    }
}
