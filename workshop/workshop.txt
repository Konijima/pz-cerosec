# The Steam Workshop item, as the game's own submit screen reads it.
#
# The format is SteamWorkshopItem.readWorkshopTxt (javap -p -c on the shipped
# projectzomboid.jar). Every line is trimmed; a blank one, or one starting with
# "#" or "//", is skipped, which is why these comments are legal. The keys it
# knows are id=, title=, description=, tags=, visibility= and version= (read and
# ignored). "description=" may repeat: each line is appended to the one before
# with a single newline between them (BootstrapMethods #9, "\1\n"), so a blank
# line in the description is a bare "description=" here. "tags=" is split on ";"
# and the legal set is media/WorkshopTags.txt, one tag a line. "visibility=" is
# one of public, friendsOnly, private, unlisted.
#
# "id=" is written by Steam after the first upload: the submit screen calls
# writeWorkshopTxt the moment you leave its second page, and that rewrite puts
# version=1 first, then id=, title=, one description= a line, tags= and
# visibility=. It does NOT keep these comments. Copy them back from git if you
# want them, and see docs/RELEASE.md for the rest of the checklist.
#
# ---------------------------------------------------------------------------
# THE IMAGES IN HERE, AND WHY THEIR URLS ALREADY WORK
#
# Steam renders [img] from a URL and has no idea what is inside the uploaded
# item, so nothing in the mod's own folder can be shown. Two hosts, and each
# has a reason:
#
#   * the banner and the seven section headers are served out of the GitHub
#     repository, https://raw.githubusercontent.com/Konijima/pz-cerosec/main/
#     ..., which answers with access-control-allow-origin: * and therefore
#     survives the crossorigin="anonymous" Steam puts on a third-party image.
#     They are versioned with the mod, so the page cannot drift from the build,
#     and the URLs below are FINAL: no line here has to be edited at upload.
#     The one thing that has to be true is that the repository is public before
#     the item is (docs/RELEASE.md steps 16 and 17) and that workshop/img/ is
#     committed on main.
#
#   * the ten screenshots are uploaded to the ITEM, because that is where a
#     Workshop screenshot belongs -- it shows in the item's own gallery as well
#     as in the description. Their URLs do not exist until the upload, so each
#     one has a commented slot below naming the file from workshop/SHOTS.md.
#     Turning a slot on is one edit: drop the "#", keep the "description=", and
#     put the image address between the tags.
#
# Every image is authored at 630 px wide, which is not a taste: Steam's own
# stylesheet caps a description image at
#     .workshopItemDescription img { max-width: 630px; }
# (public/css/skin_1/workshop.css). Wider is not shown wider, it is scaled
# down, and a scaled-down bitmap face comes back with grey edges.
# ---------------------------------------------------------------------------

description=[list]
description=[*][b]A real terminal.[/b] Sixty columns by twenty, a BIOS, a login prompt, a shell. Two survivors at one computer type on the same glass.
description=[*][b]Files, permissions, accounts.[/b] Owner, group and other, octal and symbolic modes, symbolic links, and [b]su[/b] and [b]sudo[/b] with a real [b]/etc/sudoers[/b] behind them.
description=[*][b]The prompt is the script language.[/b] [b]sh[/b]'s own grammar: [b]if[/b], [b]while[/b], [b]for[/b], variables, [b]$( )[/b], pipes, redirects, background jobs. [b]cron[/b] runs a crontab while nobody is watching; [b]edit[/b] turns the screen into an editor.
description=[*][b]The building, under /dev.[/b] A character device for every door, switch, lock and window the machine can reach: [b]dev light0 off[/b], [b]dev door1 open[/b]. A vanilla Motion Sensor becomes a [b]sensorN[/b] a script can poll.
description=[*][b]Hardware you have to fit.[/b] Nothing is a device because of what it is. A contact, a relay, an electric strike or a door operator goes on the fixture itself, with a screwdriver and some Electricity. Find them in an electrician's van, or read the [b]CeroSec Field Wiring Guide[/b].
description=[*][b]Floppy disks.[/b] A 3.5 inch disk with a filesystem of its own: [b]newfs[/b], [b]mount[/b], copy your notes on, write on the label, carry it across town.
description=[*][b]A manual you have to find.[/b] Three volumes, printed in 1993, spawning where a book about a computer would have been shelved. Your survivor goes on working while you read.
description=[/list]

description=[*][b]Coax, for the premises.[/b] Every computer of one premises shares a segment and an address that comes out of where it stands. A premises is not a building: a house is one, a mall is thirty shops on thirty segments. [b]arp[/b], [b]ruptime[/b], [b]rlogin[/b], [b]rsh[/b], [b]rcp[/b], and trust files so you stop typing the password.
description=[*][b]The telephone, for the county.[/b] One line per premises, one call at a time, a seven-digit number the firmware announces at power-on and nowhere else. [b]cu[/b] dials it at 2400 baud.
description=[*][b]Packet radio, for after the power.[/b] A two-way radio the machine can reach becomes its TNC, and a callsign in [b]/etc/callsign[/b] makes it a station. [b]cu -l /dev/radio0[/b] opens the box's own prompt with the TNC-2's command set. The only link that outlives the county's power.

description=[b]The budgets are why it is safe on a public server.[/b] A script is stepped, never looped to the end, so a [b]while true[/b] somebody left running costs that machine its own share and nothing else. A disk is 64 KB, a file 4096 bytes, a machine 512 nodes; four jobs is four jobs and the fifth remote session is refused. [b]Nothing a player types is ever handed to Lua[/b]. Admins get a debug window and a diagnostics floppy.

description=Six things have no 1993 model and are kept anyway. Rather than pass them off quietly they are printed in the in-game Volume 1, on a page called [i]What is not Unix here[/i]: [b]help[/b], [b]dev[/b], [b]mkpasswd[/b], [b]edit[/b], [b]sudo[/b], and jobs that belong to the machine rather than to the shell.

description=
description=[b]Does it need any other mod?[/b] No. No dependencies, no bundled libraries, vanilla Lua only.
description=
description=[b]Can I add it to a save I am already playing?[/b] Yes. The computers were always there; this gives them a disk the first time you switch one on. Removing it leaves them as the furniture they were.
description=
description=[b]Will it slow the game down?[/b] It is budgeted rather than trusted: the ceilings above are the whole of what one computer can cost. Nor can an update break what you built, because every release photographs the shape it writes to the save and the next has to walk it forward.
description=
description=[b]Does it work in multiplayer?[/b] Yes, and it was built that way rather than adapted. Dedicated-server testing is next on the list, so if you run one, say what you find in the comments.
description=
description=[b]Does it conflict with other mods?[/b] Nothing known: it adds its own items and menu entries and overrides no vanilla file. A mod that replaces the desktop computer object itself would collide.
description=
description=[b]Build 41?[/b] No, and there will not be one. Build 42 only, on 42.20 and up.
