CeroSec

Made by Konijima · Project Zomboid · Build 42

THE NETWORK NEVER DIED.

CeroSec puts a small Unix on the desktop computers that were already standing in Knox County. Right-click one to switch it on, right-click again to sit down at it, and a green 60x20 terminal opens on a BIOS boot line and a login prompt. Behind the prompt is CeroSec OS 1.0, a 1993 Unix with files, permissions, accounts, an editor, a shell language and cron. The disk belongs to the machine and not to you: walk away and come back to the same session still logged in, and a computer you unplug and carry across the county keeps everything that was on it.

REAL UNIX TERMINAL. NETWORKING AND REMOTE ACCESS. MULTI-USER SYSTEM. 1993 REALISTIC ENVIRONMENT. FOR PROJECT ZOMBOID.

Features

  • A real terminal. Sixty columns by twenty, a BIOS that counts the memory, a login prompt, a shell. Two survivors standing at one computer read and type on the same glass.
  • Files, permissions and accounts. Owner, group and other, three octal digits, symbolic modes, symbolic links. Accounts, groups, su and sudo with a real /etc/sudoers behind it.
  • An editor. edit turns the screen into one: Tab saves, Escape leaves and asks first.
  • Shell scripting. The prompt is the script language, with sh's own grammar: if, while, for, variables, $( ), pipes, redirects, background jobs, jobs and kill. cron runs a crontab on the minute hand while nobody is watching.
  • The building, under /dev. One file per door, light switch, lock and window the machine can reach, worked by name: dev light0 off, dev door1 open, dev lock1 toggle. Drop a vanilla Motion Sensor in a room and it becomes a sensorN a script can poll.
  • Three ways out of the case. Every computer in a map building is on one length of coax with the others, with its own address: arp, ping, ruptime, rlogin, rsh and rcp, and trust files that spare you the password. Past the building, a modem dials the county at 2400 baud with cu. Past the county's power, a two-way radio becomes the machine's TNC and call raises another station by callsign, where anybody tuned to that frequency hears the connect.
  • Floppy disks. A 3.5 inch disk with a filesystem of its own: newfs, mount, copy your notes onto it, carry it across town.
  • A manual you have to find. Three volumes, the User's Guide, the System Administrator's Guide and the Programmer's Guide, printed in 1993 and spawning where a book about a computer would have been sold or shelved. They open as a book on your screen and the survivor goes on doing whatever they were doing.
  • Server-safe by construction. Every script runs on a step budget, the disk is 64 KB, a file is 4096 bytes, and four jobs is four jobs. Nothing a player types is ever handed to Lua.

Getting started

The first ten minutes, in order:

  • Right-click a desktop computer and choose Turn on computer. It needs power in the room.
  • Right-click it again and choose Use computer. Your survivor walks over and sits down.
  • At login: type admin, then press Enter at the password: a shipped machine has admin and root, both with no password yet.
  • Type help for the commands, then dev to see the doors, lights and locks this machine can reach. Try dev light0 off.
  • Type exit, or close the window, and walk away. The screen keeps running and is exactly as you left it next time.

Multiplayer

Every computer's disk lives on the server, and every command is run there. A client asks; it never decides. Two survivors at one machine share the screen, a third can rlogin in from the machine next door, and what one of them writes the others read.

The budgets are the reason this is safe to run on a public server. A script is stepped, not looped to the end, so a while true somebody left running costs that machine its own share and nothing else. A remote session costs the far machine, not yours. Four sessions may come in at once and the fifth is refused.

Early release

This is version 0.1.0. Everything listed above is finished, tested and documented. What is being built now:

  • Hardware modules you install on a door yourself, instead of a building that is wired to the computer from the start.
  • One phone line per machine, with seven-digit numbers, instead of one line per building.
  • mheard, so a radio station can tell you who it has heard lately.
  • A debug window for server admins.

Bugs and questions go in the comments here. The source, the issue tracker and the full documentation are at github.com/Konijima/pz-cerosec, which opens at release.

Made by Konijima

  • No dependencies. Vanilla Lua, nothing bundled, nothing required.
  • Build 42 only, and there will be no Build 41 version.
  • Safe to add to a running save. Removing the mod leaves the computers as furniture; the manuals and floppies in inventories are lost.
Faithful to Unix, nothing invented. Where a real /bin/sh, a real cron, a real rlogin or a real Hayes modem would answer a certain way, this machine answers the same way, refusals included. A behaviour with no real-world model is a behaviour we questioned.
